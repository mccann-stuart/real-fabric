# Unactioned findings from the open PR consolidation

Recorded on 30 September 2026 after [super PR #243](https://github.com/mccann-stuart/real-fabric/pull/243) merged at `8dc8d08f12a3ad315816f7d2d5e5d2d1938d1da0`. These are the remaining engineering or verification gaps observed during that review. The [PR disposition record](./open-pr-consolidation-2026-09-30.md) covers all 39 source proposals; a deferred optimisation is not, by itself, evidence of a defect.

| Priority | Finding and evidence | Follow-up needed |
| --- | --- | --- |
| P1 | **Relay-wide browser bearer remains exposed.** Room creation and joining still return the configured relay credential through [`src/worker/index.ts`](../src/worker/index.ts). The credential grants relay-wide publish and subscribe authority; the application labels routing cooperative. This is the already tracked [SEC-01](../security/security_issues.md#sec-01--room-creation-and-joining-disclose-a-relay-wide-publishsubscribe-bearer), not a new finding from #243. | Adopt a relay-enforced grant scoped to room and participant publication/subscription rights without a participant cap, then prove denial outside the grant in a browser-to-relay trace. Token rotation or application-only claims do not close this issue. |
| P2 | **Floor release has no AI-bound turn lease.** [`Room.releaseFloor`](../src/worker/room.ts) validates presenter authority and an active AI target, and #243 now cleans stale holders and queues. Release still accepts an AI ID without a current turn identifier. [SEC-03](../security/security_issues.md#sec-03--unvalidated-ai-identifiers-can-wedge-or-pre-empt-the-global-floor) is therefore only partially mitigated. | Bind release to a short-lived turn lease for the current AI and test stale/replayed releases, removal, reconnect expiry and concurrent request ordering. Keep Milestone 3 floor authority open until that is verified. |
| P3 | **Shared activity recency is still self-reported.** [`Room.markActive`](../src/worker/room.ts) already rejects a caller targeting another participant; [`test/room-service.test.ts`](../test/room-service.test.ts) covers that denial. The [SEC-13](../security/security_issues.md#sec-13--any-participant-can-spoof-another-participants-activity) tracker had not reflected this partial fix. A client can still report its own activity without trusted evidence of publication, and [`RoomSession`](../src/client/session/RoomSession.ts) also reports the viewer's activity when it receives a remote first object. Shared `lastActiveAt` remains an unreliable proxy for who spoke. | Define whether shared recency should represent membership activity or observed speech. For speech, derive display state from each listener's observed media or a trusted relay event rather than an ordinary client request. Add tests for the chosen meaning and rate limits. |
| Verification | **The changed mixer worklet lacks a lasting source-level regression test.** #243 compared the actual [`mixer-worklet.js`](../public/audio/mixer-worklet.js) with its previous per-sample behaviour for ordinary, wrapped and greater-than-ring writes in an ad hoc Node VM check. No test in `test/` executes that worklet source, so the greater-than-48,000-sample case is not protected by CI. | Add a focused worklet-source test for ring wrap, writes longer than one ring and mixed output; run the separate Gate 2 acoustic checks on reference hardware. |
| Verification | **Live audio was not reaccepted on the consolidated head.** The local browser run verified entry, room creation, presenter simulation, graph consent and the leave dialog. Its Worker had no usable relay credential and the reachability probe timed out. The earlier Gate 1 trace documents the pre-existing transport boundary, not an acoustic test of #243's mixer and concealment changes. | Re-run browser-to-relay audio and acoustic loopback/endurance checks with an authorised, usable relay credential and reference devices before claiming live acceptance for the consolidated audio path. |
